# 架构总览

## 目标
建立一套能支撑长期开发的大型开放世界 2.5D 西幻 RPG 底层架构，具备高自由度、数据驱动、可保存、可测试、可扩展。

## 核心原则
1. 数据与逻辑分离。
2. 内容与系统分离。
3. 尽可能数据驱动。
4. 系统低耦合、高内聚。
5. 避免万能 Manager 与 God Object。
6. 不把玩家能力写死在 Player，不把 NPC 数据写死在 NPC 脚本，不把技能逻辑写死在 Skill Data，不把装备外观写死在装备逻辑。
7. 任务文本与任务逻辑分离；对话文本与对话执行系统分离。
8. 所有重要世界状态可保存。
9. 随机系统统一管理。
10. 支持大量 NPC、装备、技能、任务与地图，但避免过度工程化。

## 组合式自由框架
不以“玩家能做什么”为单位写死系统，而是建立可组合的基础块：
- `Action`：一次可执行的行为（战斗、逃跑、偷窃、开锁、说服、交易、钓鱼等）。
- `Interaction`：一个可交互对象暴露的选项集合。
- `Condition`：可判定的前置条件。
- `Effect`：可执行的后果。
- `Event`：触发与广播。
大量玩法由 Condition + Effect + Interaction + Event 组合而成。

## 稳定身份
- 运行时实体（Actor、物品实例、任务实例等）使用稳定 ID。
- 内容定义使用内容 ID；存档引用这些 ID，而非 Scene Tree 路径。

## 服务组织
- Service/System：无场景依赖的规则逻辑，可被 autoload 或普通节点承载。
- Component：挂到 Actor/Interactable 上的可组合能力。
- Resource：数据定义。
- EventBus：系统间解耦通信。

## 分层约束
- 数据层不得依赖表现层。
- 逻辑层不得直接操作具体 UI 节点。
- 表现层通过服务接口读取状态、通过事件订阅变更。
